# 沟通规范

> author: `huangshu`
> 用途: 记录当前 author 与 agent 协作时的稳定沟通规范，帮助 agent 写状态更新、收尾汇报、风险报告、会议整理和文档说明。

本文件是当前 author 私有沟通约定。称呼、昵称、会议转写别名和更细的个人偏好写在 `沟通偏好.md`，具体任务过程写在当前任务 `process.md`。

## 速查

| 场景 | 做法 |
| --- | --- |
| 工作中状态更新 | 说明正在做什么、发现了什么、下一步是什么。 |
| 发现风险 | 先说风险和影响，再说证据、已尝试动作和建议。 |
| 收尾汇报 | 简短说明改动、验证、未完成风险和是否需要用户决定。 |
| 文档引用 | 只放链接和一句话用途，不复制权威正文。 |
| 会议转写整理 | 保留结论、行动项、争议和人名映射；不把原始长文塞进公共入口。 |
| 需要用户确认 | 直接问阻塞问题，说明为什么必须确认。 |

## 基本风格

- 默认使用简体中文。
- 先结论，后证据；复杂问题再给方案对比。
- 不把“我觉得”“应该没问题”当验收结论，要给可验证证据。
- 不用行话堆叠掩盖不确定性；不确定就说明不确定和下一步验证方法。
- 不在索引、启动文件、主规则里复制其他文档正文，避免一处改动多处同步。
- 不把过程文档写成新的待执行任务，避免其他 agent 误启动旧工作。

## 报告格式

| 类型 | 建议结构 |
| --- | --- |
| 状态更新 | 当前进展；发现；下一步。 |
| 风险报告 | 问题；影响范围；证据；建议处理；是否阻塞。 |
| 收尾汇报 | 改了什么；验证了什么；还有什么风险；是否已提交/是否待提交。 |
| 设计说明 | 决策；原因；约束；被否决方案；后续验证。 |
| 会议整理 | 背景；结论；行动项；负责人；时间；待确认问题。 |

## 人名和昵称

- 公共人名、账号、昵称先查 `项目大脑/初始分工表.md`。
- 当前 author 的私有别名和沟通偏好查 `沟通偏好.md`。
- 会议 AI 转写里的错别字、谐音名、简称，应补到对应用户的私人 `沟通偏好.md` 或 `职责范围.md` 的昵称区域。

## 维护规则

- 新规则必须是当前 author 长期可复用的沟通经验。
- 团队通用规则不写到根目录 `沟通规范.md`；应先在任务记录中沉淀，再由 leader 判断是否进入 `主规则.md`、`主流程.md`、`docs/规则/`、公共 skill 或对应 docs。
- 本文件只写沟通方式，不写具体任务过程、bug 结论或代码实现细节。
