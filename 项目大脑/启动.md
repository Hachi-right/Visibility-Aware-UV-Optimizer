# 启动

本文件只做冷启动入口，不展开目录核查细节。具体检查和目录补齐由 skill `项目大脑/skills/project-startup-check/` 执行。

## 0. 私人上下文前置（在阶段提示之前）

运行启动检查（§1）并识别到 `author` 后、**任何面向用户的启动汇报之前**，须先读取：

1. `项目大脑/用户/{author}/私有流程.md`
2. `项目大脑/用户/{author}/私有规则.md`
3. 若 `私有流程.md` 定义了「冷启动必读扩展」，按该表继续读取

**例外**：`next_action=confirm_author` 时尚无 author，跳过本节；仅用 §0.1 默认话术请用户确认远程账号名，确认后重跑启动检查并回到本节。

## 0.1 阶段提示协议

启动汇报须交付以下**信息要素**（缺一补问，有则写入同一次汇报）：

| 要素 | 含义 |
| --- | --- |
| author 识别 | 当前 author、用户描述（成员/角色/职责摘要） |
| task 指针 | 当前 `task_folder`、任务名、状态、摘要 |
| 检查错误 | 启动检查 `errors` / `warnings`（无则写「无」） |
| 收件计数 | 当天收件：`待处理` 件数 + 各件一句摘要；`已处理` 只计数 |
| 加载摘要 | 已读的公共/私人文档与 skill 路由要点 |
| 待确认项 | author 或 task 指针存疑、四件套缺失、需切换/新建任务等 |

**呈现优先级**：若 author `私有规则.md` 定义了「冷启动汇报格式」，**以私人规则呈现为准**，不要求逐字使用下表默认话术。

**默认话术**（无私人「冷启动汇报格式」时使用；可合并为一到两次输出，不必拆成八条独立消息）：

| 时机 | 默认话术 |
| --- | --- |
| 启动检查开始前 | `开始启动项目大脑` |
| 识别 author 后 | `识别到当前用户: {author}` + 用户描述 + 请用户核对是否正确 |
| 识别 task 后 | `找到当前任务目录: {task_folder}`（或 `新建…`）+ 任务摘要 + 请用户核对 |
| 启动检查结束后 | `启动阶段结束` |
| 读公共流程前 | `开始加载公共流程和规则，请稍等。` |
| 读私人流程前 | `开始加载{author}用户的私有流程和规则，请稍等。` |
| 读任务上下文前 | `开始加载{task_folder}任务的上下文，请稍等。` |
| 全部加载完毕 | `加载结束，可以开始工作了。` |

如果用户已经给出目标且信息足够，加载完毕后直接开始正式工作；如果信息不足，停下来问用户，不要假装已经能继续。

## 1. 运行启动检查

每次会话先运行：

```powershell
python 项目大脑/skills/project-startup-check/scripts/startup_check.py --repo-root .
```

如果本轮请求需要修改仓库文件，可加上：

```powershell
--intends-file-change
```

如果仓库根目录没有 `workstate.json`，先由用户确认远程账号名，再运行：

```powershell
python 项目大脑/skills/project-startup-check/scripts/startup_check.py --repo-root . --author "{author}"
```

本轮会修改文件时，启动检查只提示当前是主工作区还是独立任务副本；随后读取 `start-project-task/references/worktree-gate.md`，按冲突、并行、主线稳定性与是否需要独立保存/交接决定是否创建 worktree。它不是阻断启动的 `next_action`。

## 2. 按 next_action 继续

| `next_action` | 处理方式 |
| --- | --- |
| `confirm_author` | 无法确认 author；请用户确认远程账号名，再用本文件第 1 节的 `--author` 命令重跑。 |
| `select_start_resume_or_fork_task` | `workstate.json.task_folder` 为空；先读 `项目大脑/用户/{author}/tasklist.md`，再按用户意图选择 `start-project-task`、`resume-project-task` 或 `fork-project-task`。 |
| `read_current_task_then_main_flow` | 当前任务有效；完成 §0 私人上下文前置后，进入 §4 移交主流程。 |

## 3. Skill 搜索根目录

项目大脑的 skill 搜索根目录只有两处：

- 公共 skill: `项目大脑/skills/{skill-name}/`
- 当前 author 私有 skill: `项目大脑/用户/{author}/skills/{skill-name}/`

本文件和项目大脑索引里的 `skills/{skill-name}/` 都是相对 `项目大脑/` 的路径；不要理解为仓库根 `skills/`，也不要跳过项目大脑去 `.agents/skills/` 查找同名能力。

搜索根目录不等于创建落点。新建 skill / MCP / hook / 辅助落盘默认放当前 author 私有区；只有 `tech-lead` 通过 leader 公共化流程，才能放到私有区外。

公共 skill 分类入口：`项目大脑/skills/index.md`（按场景读 `skills/索引/{分类}.md`，不冷启动全量读）。

## 4. 移交主流程

启动检查完成且 §0 私人上下文前置已读后，把控制权交给 `项目大脑/主流程.md`：

1. 读取 `项目大脑/主流程.md`。
2. 按 `主流程.md` §1 必读加载链：公共索引、**§2 硬规则速查**（不读 `主规则.md` 全文）、当天收件文件头。`私有流程.md` 已在 §0 读取，此处标记已读，不重复加载正文。
3. 按 `私有流程.md` 继续加载当前任务上下文及冷启动必读扩展中尚未读取的文档；私人 `index.md`、职责范围、其余软上下文和经验文档只在触发场景出现时按需读取。
4. 按 §0.1 信息要素组织一次启动汇报；呈现遵循 author `私有规则.md`「冷启动汇报格式」（若有）。
5. 如果本轮目标已经足够明确，直接开始正式工作；如果信息不足，停下来问用户。

如果当前任务需要 CodeGraph、cc-artifact、Cursor/CodeWhale/Codex MCP 适配或第三方辅助工具安装，按需读取 `项目大脑/第三方辅助工具.md`；缺工具时优先开子 agent 安装或初始化，不阻塞主流程。

## 5. 上下文重载

触发与动作见 `项目大脑/主流程.md` §5「重载与防跑偏」。收到 compact/长会话 hook 提醒后，必须实际读取落盘文件，不要把提醒当作已恢复上下文。
