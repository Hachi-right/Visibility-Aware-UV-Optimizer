# 主流程

本文是项目大脑的 **Runtime Hub**：冷启动加载顺序、L3 硬规则速查、条件加载总表和重载规则。规则详情按需读 `主规则.md` 或被指向的 skill；不在本文写操作步骤正文。

**维护契约**：新增 skill 触发只改 §3；新增 L3 硬规则改 §2 一行 + `主规则.md` 详情；格式/步骤只改对应 skill reference。

## 1. 必读加载链

| 顺序 | 读取文档或 skill |
| --- | --- |
| 1 | `项目大脑/index.md` |
| 2 | **本文 §2 硬规则速查**（不读 `主规则.md` 全文） |
| 3 | `项目大脑/用户/{author}/私有流程.md` |
| 4 | 当前 author `收件/` 中**当天**（文件名 `YYYY-MM-DD-*`）各 md 文件的**文件头**（至 `---` 为止）；`待处理` 件口述摘要，`已处理` 件只计数（见 §3 → `project-inbox-rules`） |

> **团队经验**：入口 `团队经验/INDEX.md`；**任务开始时**按 INDEX「主动检索触发」点读 1–3 篇 `entries/`；冷启动不读 entries（C1）。
>
> **团队公理**：入口 `公理/index.md`；**任务开始时**按 index「任务开始路由」点读 0–2 篇 `entries/`；冷启动不读 entries（T4）。
>
> **个人经验**：入口 `用户/{author}/经验/INDEX.md`；**任务开始时**同样按 request/goal 点读 0–3 篇 `entries/`；冷启动不读 entries；尚无 entries 时在 `process.md` 标注「暂无」。

改仓库文件前，先确认 `workstate.json.task_folder` 指向当前任务；若无 task，先建 task 再改文件（见 §2 R4、`主规则.md` §任务留痕）。

## 5. 重载与防跑偏

**触发**：新会话、上下文压缩、长时间运行、任务恢复、目标变化、大改、阶段验收、提交前、继续或 fork 旧任务前。

**动作**：

1. 重读 `workstate.json`、当前任务 `process.md`、`design.md`、`任务范围.md`、`任务指标.md`。
2. 重读 `项目大脑/用户/{author}/私有流程.md`、`私有规则.md`。
3. 重跑 §1 必读链（含 §2 硬规则速查）；**不**默认重读 `主规则.md` 全文。
4. 按当前目标从 §3 条件表按需加载；重读 `职责范围.md`、`tasklist.md` 或查询私人 `index.md`。
5. 重载后确认当前目标、WIP、已定决策、验收标准和下一步；有矛盾先收敛或问用户。
6. 需求很大、边界不清、跨模块或评估复杂时，先拆阶段、定验收，再一阶段一阶段执行；不要直接大范围实现。
7. 重要决策写 `design.md`；过程、风险、验证写 `process.md`；范围与证据写 `任务范围.md`；阶段指标写 `任务指标.md`。
