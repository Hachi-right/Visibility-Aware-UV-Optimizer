# worktree 闸门

## 先判断，再决定在哪里工作

`main` / `master` 是日常默认工作区，不再因为“要改文件”而自动新建 worktree。所有改仓库工作仍必须有 task 流水；工作位置由下列闸门决定。

### 可直接在 main / master 工作

- 会议纪要、设计讨论、资料整理、文案或小范围需求修改。
- 能在当天完成、验证，并且不需要多套试验方案或交接给他人继续做。
- `main` 没有会与本任务重叠的重要未提交改动。
- 修改期间不会让团队主线长期处于不可运行状态。

### 建议使用 worktree

- 预计跨天、需要反复试验，或完成时间无法确定。
- 涉及多个模块、需要 review / 交接，或需要保留独立验收环境。
- 会临时破坏可运行状态、生成大量试验产物，或需要比较多套方案。

### 必须使用 worktree

- `main` 有重要未提交改动，且本任务可能改到相同文件或同一功能区域。
- 多人并行修改同一功能或同一文件区域。
- 用户明确要求隔离、备选方案、独立验收环境或可回退试验。

判断以“是否会冲突、是否会让主线不稳定、是否需要独立保存或交接”为准，不以文件数量或工期天数机械判定。命中“必须”项时，使用 `项目大脑/skills/create-project-worktree/`；命中“建议”项时，先用人话说明原因，由用户决定。

## 创建 worktree 时

该 skill 统一处理：

| 内容 | 用途 |
|------|------|
| author | 与远端账号一致 |
| Git identity | `user.name` / `user.email` 与 author 锚定 |
| workstate.json | `author`、Git identity 和任务目录一致 |
| 任务目录 | 同时创建 `process.md` 与 `design.md` |

## 已在独立任务副本时

如果当前已经在任务分支，脚本读取根目录 `workstate.json`。

| 状态 | 行为 |
|------|------|
| 没有 `workstate.json` | 需要显式传入 `--author`，再创建任务目录并写入状态 |
| `task_folder` 为空 | 直接创建任务目录并写入状态 |
| `task_folder` 指向具体任务 | 需要用户确认后传入 `--replace-current` |
