# 学习流程

## 触发类型

| 类型 | 判断标准 | 处理方式 |
| --- | --- | --- |
| 明确指导 | 用户直接说“以后要这样”“记住这个偏好”“沟通时按这个方式”“测试时重点看这个”。 | 可直接更新对应私人软上下文，同时记录来源和日期。 |
| 周期性总结 | 用户要求总结近期协作，或任务收尾时发现同一偏好、验收习惯、沟通要求多次出现。 | 先找证据，再写长期稳定结论；证据不足时只写当前任务 `process.md`。 |
| 候选观察 | agent 只观察到一次行为，或无法判断是长期习惯还是当前任务要求。 | 写入当前任务 `process.md` 的候选观察，不更新私人软上下文。 |

## 证据规则

- 明确用户指令可以作为强证据。
- 多次任务记录、重复纠正、稳定验收要求可以作为周期总结证据。
- 会议转写和外部文档只在能确认对象是当前 author 时使用。
- 不写密码、密钥、隐私信息、无法确认的性格猜测或情绪判断。
- 不把单个任务的临时目标、WIP、bug 状态写成长期习惯。

## 写入步骤

1. 确认当前 author 和当前任务目录。
2. 读取现有五个私人软上下文文件，避免重复写入。
3. 按 `private-context-targets.md` 选择目标文件。
4. 用短条目写清场景、偏好/事实、来源日期或来源任务。
5. 如果新结论推翻旧结论，保留新口径并说明旧口径废弃原因。
6. 在当前任务 `process.md` 追加学习记录：来源、判断、写入文件、未写入内容和原因。

## 边界

- 只更新当前 author 自己的 `项目大脑/用户/{author}/`。
- 不能直接改其他 author 的私人用户区。
- 不能让私人软上下文覆盖 `主规则.md`、`职责范围.md`、代码规范、模块约束或用户当次明确指令。
- 团队通用经验应先在任务里验证，再由 leader 提升到公共文档或公共 skill。
