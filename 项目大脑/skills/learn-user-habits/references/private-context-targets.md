# 私人软上下文写入目标

## 文件分工

| 目标文件 | 写入内容 | 常见来源 |
| --- | --- | --- |
| `用户画像.md` | 当前 author 的长期稳定身份、职责背景、昵称、转写别名、识别线索。 | 初始分工表、用户确认的人名/昵称、长期职责说明。 |
| `工作习惯.md` | 当前 author 稳定的工作流、阶段粒度、验收偏好、工具习惯、停止条件。 | 用户多次要求的验收方式、任务推进节奏、工具使用偏好。 |
| `协作灵魂.md` | 当前 author 与 agent 协作时的软基调、协作姿态、边界感和长期协作原则。 | 用户对 agent 行为基调、协作方式、公共/私人边界、长期记忆整理方式的明确指导。 |
| `沟通规范.md` | 当前 author 与 agent 协作时的稳定沟通规范、报告结构、风险表达和会议整理规则。 | 用户对状态更新、收尾汇报、风险报告、会议整理和文档说明方式的稳定要求。 |
| `沟通偏好.md` | 当前 author 希望 agent 如何汇报、提问、提醒、称呼、解释问题。 | 用户对回复风格、状态更新、风险报告、总结方式的明确指导。 |

## 写法

- 优先追加到已有章节；没有合适章节时新增二级标题。
- 条目要短，写清“场景 + 偏好/事实 + 来源”。
- 同类内容已经存在时，更新原条目，不重复追加。
- 需要证据时写来源任务或日期，例如：`来源: YYYY-MM-DD 当前任务 process.md`。
- 周期性总结使用“观察到”或“稳定偏好”表述；明确指导使用“用户明确要求”表述。

## 不同内容的落点

| 内容 | 写入位置 |
| --- | --- |
| “每阶段要测试并入库” | `工作习惯.md` 的验收或收尾习惯 |
| “报告要简短，先说结论” | `沟通规范.md` 的报告结构；个人细节写 `沟通偏好.md` |
| “可靠胜过表演，别做空泛承诺” | `协作灵魂.md` 的核心基调 |
| “某昵称对应某成员” | `用户画像.md` 或 `沟通偏好.md` 的称呼与别名 |
| “本任务下一步要做什么” | 当前任务 `process.md` |
| “某设计决策为什么这样做” | 当前任务 `design.md` |
| “团队所有人都要遵守的规则” | 先写当前任务记录，再由 leader 判断进入 `主规则.md`、`主流程.md`、`公理/`、公共 skill 或对应 docs |
