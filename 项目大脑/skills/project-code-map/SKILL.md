# 代码地图

本 skill 是公共 skill，但日常写入当前 author 私有代码地图。它把“找代码”的结果沉淀成可复用地图，减少下次全局搜索和重复造轮子。

代码地图不是工具排队，而是代码搜索前的查询规划层。验收目标是在从未搜索过的代码上，用更短耗时获得更高质量、更全面、更准确的命中。

## 查询规划硬规则

CodeGraph 和 `rg` 都依赖已经猜对一部分锚点：符号名、文件名、目录、协议、配置 key、业务词或相似功能名。猜错锚点时，它们会漏掉目标，或者命中相似但错误的代码。

凡搜索代码、定位入口、调研相似实现、评估复用或准备改代码，第一轮工具查询前必须产出“查询规划卡”。没有查询规划卡，不得直接 CodeGraph 或全仓 `rg` 裸搜。

地图结论是搜索假设，不是最终事实。若当前源码和地图断言冲突，以源码为准，并把地图记录降级为待更新候选。

## 最小流程

1. 定目标：写清要找的对象、动作、原因，以及可能归属的端、模块或目录。
2. 查地图：先读当前 author 私人 `代码地图/index.md` 和 `差异列表.md`，再读公共 `项目大脑/代码地图/index.md`；只打开相关主题。公共地图为空时快速记为“公共缺失”，不要在空索引上耗时。
3. 写查询规划卡：列出候选入口/目录、关键词/别名、UI/协议/配置/日志/相似功能切入点、排除项和待验证问题。
4. 带卡搜索：有稳定文件、类名、函数名或协议字段时，用 CodeGraph 验证调用链、影响面和动态关系；只有目录、配置、文案、资源 key 或非代码文本时，用 `rg` 在候选目录内搜索。第一轮工具查询必须引用规划卡里的锚点。
5. 校准再扩展：命中相似但错误的代码，先补别名和排除项；地图缺失、过期或假设失败时，说明失败原因后再扩大目录，最后才全仓兜底。
6. 收敛后维护：结论必须包含稳定入口、证据和追踪路径；普通任务只把稳定经验写入当前 author 私人代码地图，并按需更新差异列表。

## 查询规划卡

最小字段：

| 字段 | 必填内容 |
| --- | --- |
| 搜索目标 | 要找什么、为什么找、目标属于哪个端或模块的初判。 |
| 已读地图 | 私人 index、差异列表、公共 index，以及打开过的相关主题。 |
| 候选入口/目录 | 可能直接跳转的文件、类、函数、协议、配置、表或稳定目录。 |
| 关键词/别名 | 业务词、UI 文案、日志词、配置 key、协议字段、旧称、相似功能名。 |
| 反向追踪路径 | 从 UI、协议、配置、日志、数据表、服务端接口或相似功能倒推代码的路径。 |
| 排除项 | 容易误入的相似模块、历史 demo、工具目录、过期入口或非当前运行链路。 |
| 待验证问题 | 需要用源码确认的新鲜度、调用关系、读写路径、配置来源或影响面。 |
| 首轮工具查询 | 计划给 CodeGraph / `rg` 的 3-8 个锚点，或候选目录内的限制搜索。 |

地图无命中时，仍要先写最小假设表再搜：`候选目录`、`候选消息/协议`、`候选状态或数据容器`、`候选展示/执行组件`、`排除目录/相似误区`。不要把“地图无命中”当作立刻全仓裸搜的理由。

## 工具角色

- CodeGraph：用于稳定文件/符号/协议字段已成形后的调用链、影响面和动态关系验证；查询应使用规划卡里的 3-8 个锚点。
- `rg` / `rg --files`：用于配置、文案、资源、非符号文件、命中规模评估，或 CodeGraph 未覆盖的文本枚举；优先限制在规划卡给出的目录内。
- 两者都不是入口判断器。入口判断先由代码地图、查询规划卡和源码验证共同完成。

## 质量门槛

定位结论至少覆盖：

- 稳定入口：文件路径加类名、函数名、协议字段、配置 key 或表名。
- 证据：CodeGraph 结论、限制目录搜索摘要、源码阅读结论或来源任务。
- 路径：调用链、读写链、配置链、协议链或 UI 到数据的反向追踪路径。
- 排除项：说明哪些相似入口被排除，为什么不是本次目标。

缺入口、配置/协议、读写或调用路径中的关键层时，先二次收窄验证，不要急着宣称命中。

## 触发场景

- 写代码、改代码、查 bug、调试、review 前需要定位代码入口。
- 新功能开始前需要判断是否已有相似实现可复用或扩展。
- 用户问“这个功能在哪”“有没有类似代码”“从哪里改”。
- 带查询规划卡验证后找到稳定入口、模块边界或查找经验。
- 发现私有代码地图、公共代码地图或最新代码之间不一致。
- leader 周期抽取成员私人代码地图到公共代码地图。

## 读取顺序

1. 确认当前 author。
2. 先读取当前 author 私人 `项目大脑/用户/{author}/代码地图/index.md` 和 `差异列表.md`。
3. 再读取公共 `项目大脑/代码地图/index.md`。
4. 只读取和当前问题相关的主题文档；不要全量读取整个代码地图目录。
5. 读取主题文档时，先形成查询规划卡：候选入口、候选关键词/别名、稳定目录、反向追踪路径、误导项和需要验证的问题。
6. 私有地图命中时，优先使用私有候选路径、符号、协议或配置；公共地图只作对照和兜底。
7. 私有地图未直接命中但有相邻主题时，先用相邻主题缩小范围，不要立刻全仓裸搜。
8. 私有地图未命中时，再用公共地图补齐公共入口、通用术语和可复用路径。
9. 私有和公共都未命中、明显过期或需要验证调用路径时，用查询规划卡指导 CodeGraph / `rg` 验证。
10. CodeGraph 或 `rg` 命中相似但错误的代码时，先更新规划卡的排除项和别名，再扩大搜索范围。

## 写入位置

- 查询规划、CodeGraph 查询、限制目录 `rg` 或调研相似实现后，只写当前 author 私人 `代码地图/`。
- 不因日常任务直接修改公共 `项目大脑/代码地图/`。
- `tech-lead` 走 leader 公共化流程时，才从私人代码地图、差异列表、任务记录或稳定复盘抽取到公共 `代码地图/`。
- 不直接修改其他 author 的私人代码地图。

## 差异列表

每个 author 私人代码地图下保留 `差异列表.md`。它记录当前 author 私有地图和公共地图之间的差异，方便 leader 周期抽取时快速发现、自动核实、更新公共地图。

出现以下情况时，更新当前 author 的 `代码地图/差异列表.md`：

- 私有地图有稳定入口，公共地图没有。
- 私有地图和公共地图记录同一主题但路径、符号、协议、配置或查找经验不一致。
- 公共地图记录已经过期，源码验证、CodeGraph 或限制目录 `rg` 证实私有记录更接近当前代码。

差异条目使用表格，建议列：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定短 id，例如 `code-map-用户认证-入口`。 |
| `状态` | `待核实`、`已公共化待清理`、`保留私有`。 |
| `差异类型` | `公共缺失`、`公共过期`、`路径冲突`、`符号冲突`、`查找经验冲突`。 |
| `私有主题` | 私有主题文档路径。 |
| `公共主题` | 公共主题文档路径；没有则写 `无`。 |
| `私有结论` | 路径和符号，不写行号。 |
| `公共结论` | 路径和符号，不写行号。 |
| `证据` | 最近验证版本、搜索命令摘要、CodeGraph 结论或来源任务。 |
| `更新时间` | `YYYY-MM-DD`。 |

leader 更新公共地图后，核实公共记录已经覆盖该差异，再从差异列表移除对应条目。跨 author 私有区仍遵守职责边界：leader 可以读取差异列表做公共抽取；移除其他 author 私有差异条目需要该 author 会话执行或用户明确授权。

## 记录格式

主题文档使用稳定业务域或技术域命名，例如 `用户认证.md`、`API与接口.md`、`协议与配置.md`。不要按日期、单次搜索、bug 编号或临时任务名建文件。

每个主题文档建议包含：

- 最后更新时间：`YYYY-MM-DD`
- 最后验证版本：git commit 短哈希或分支基准。
- 适用场景：什么需求或问题先看这里。
- 关键入口：文件路径加函数名、类名、变量名、协议名、配置名或数据表名。
- 关键词/别名：业务词、UI 文案、日志词、配置 key、协议字段、旧称或相似功能名。
- 反向追踪路径：如何从 UI、协议、配置、服务端接口、日志、数据表或相似功能顺藤摸瓜。
- 误入相似目标：容易误搜的相似模块、历史 demo、工具目录、过期入口或非当前运行链路。
- 踩坑/捷径：推荐反向追踪路径、稳定目录、常用入口和已知排除项。
- 公共差异：如果和公共地图不同，写 `见 差异列表.md#{id}` 或在差异列表新增条目。
- 相关主题：指向其他代码地图主题或 docs 文档。
- 来源任务：当前任务目录或稳定复盘来源。

## 禁止事项

- 不在产出查询规划卡前直接调用 CodeGraph 或 `rg` 搜代码。
- 不把读取地图理解成机械顺序；读完地图后，必须带着更好的关键词、目录、入口、反向追踪路径或排除项使用 CodeGraph / `rg`。
- 不在有地图线索时直接全仓裸搜模糊词；先用地图缩小目录、入口或反向追踪路径。
- 不把地图断言当作最终事实；源码验证发现冲突时，以源码为准并更新地图。
- 不记录行号；行号容易漂移。
- 不一条搜索一个文件。
- 不把未验证猜测写成稳定入口。
- 不把业务过程、bug 复盘或长日志塞进代码地图；那些写当前任务 `process.md` 或专门 bug 文档。
- 不把代码地图当代码规范；命名和防御式编程仍看 `docs/规则/index.md` 点读分册。

## 更新规则

- 发现记录与最新代码不一致时，更新原主题文档的入口、验证版本和更新时间。
- 更新私有主题后，对照公共地图；公共缺失或不一致时，更新 `差异列表.md`。
- 如果一个主题超过 50 条入口，按稳定子主题建立下级目录和二级 `index.md`。
- 新增主题后，同步对应私有 `代码地图/index.md`；需要作为当前 author 高频入口时，再同步当前 author 私人 `index.md`。
