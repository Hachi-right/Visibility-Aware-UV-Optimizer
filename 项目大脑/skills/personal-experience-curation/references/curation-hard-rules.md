# 经验整理硬规则（L0–L3）

本文保存经验整理分层、积累触发、整理确认和求证文档规则。执行入口见 `personal-experience-curation`。

## 分层

| 层 | 名称 | 写入位置 | 提升条件 |
| --- | --- | --- | --- |
| L0 | 任务过程 | task `process.md` 等 | 默认 |
| L1 | 私人经验 | `用户/{author}/经验/` | 有来源、前因、结论、证据、复用场景 |
| L2 | leader 公共抽取 | `docs/规则/`、公共代码/资料地图 | 跨成员可复用、已验证、有前因后果 |
| L3 | 硬规则 | `主规则.md`、`主流程.md` §2 | 用户明确指定或证据足够强 |

不能把一次任务流水直接提升成公共规则，除非用户明确指定或证据足够强。分层标记：L0 任务过程、L1 私人经验、L2 公共抽取、L3 硬规则。

## 评判

- 经验候选须**先评判**再写入；按 `experience-evaluation.md` 和 `experience-curation-standards.md` 评判。
- 未来 3 个月内无复用价值、缺少证据闭环或前因后果不清 → 不提升。
- 缺少来源、前因、结论、证据或复用场景的任务流水 → 不写入经验库。

## 积累触发（替代冷启动到期检查）

**不做**每次冷启动到期检查、专用 worktree 或 running 锁。仅在以下情况整理：

- 已完成 task 新增 ≥ 5～10 个（有足够跨 task 证据）；
- 经历了高密度决策期（版本节点、重大拍板、事故复盘）；
- 用户主动要求整理；
- 用户明确要求「会议经验入库」或从会议记录整理经验时，由 `personal-experience-curation` 写/强化单条经验。

## 私人整理（personal-experience-curation）

| 项 | 规则 |
| --- | --- |
| 触发 | 积累触发条件满足；用户说整理经验；会议纪要对账后需写/强化经验 |
| 写入 | 只写当前 author 私人 `经验/entries/` + `经验/INDEX.md` |
| 求证 | 批量整理完成后写 `经验/整理确认.md`：高把握清单、低把握待确认、依据缺口 |
| 校准 | 请当前 author 校准：重要/不重要、措辞、结构、可读性 |

## 纯整理经验临时任务

- 用户单独要求「整理经验」→ 可新建独立临时整理任务。
- 只 commit/push 经验文档、私人索引等结果。
- 不得删除功能、文档、策略、调研、bug、公共化或混合任务目录。

## 使用者纠正

使用者纠正整理方法后，学到的整理经验先写入当前 author 私人 `经验/`。

## 汇报

整理完成后向用户汇报整理内容、求证文档位置和丢弃项；用户明确说「提交」才可 commit，说「推送」并经确认后才 push。
