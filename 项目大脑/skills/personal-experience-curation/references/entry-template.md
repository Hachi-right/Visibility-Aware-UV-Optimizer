# 经验认知条文模板

> **团队经验（`项目大脑/团队经验/`）**：会议落盘与公共写入**必须严格**按本模板，无例外。见 `team-experience-dual-write.md`。
> **个人经验（`项目大脑/用户/{author}/经验/`）**：非会议场景建议按本模板；会议场景若 author 私人习惯不同，个人侧可按私人模板，**团队侧仍按本模板单独写**。

每条一个独立文件，放 `经验/entries/`。命名：`{类别}{编号}_{英文主题}.md`（对齐 `personal-axioms/references/axioms/`）。



## 文件头（frontmatter）



```yaml

---

id: exp_a1_dual_goal_node_utility

category: A

created: YYYY-MM-DD

updated: YYYY-MM-DD

---

```



## 正文结构



```markdown

# {编号} · {反常点标题}



**认知**：{一两句话，读者能抓住重点}



| 字段 | 内容 |

| --- | --- |

| 认知 | {展开：判断逻辑，非步骤} |

| 为何有效 | {反推机制；为何非常见做法却有效} |

| 何时用到 | {**YYYY-MM-DD 情境**：在什么任务/争论中认识到并用到} |

| 边界 | {何时不适用；个人/不普适标注；**须含反例狩猎结果**——找到的反例及其被吸收方式} |

| 来源 | {task 路径、design 决策号、或 `ref_{YYYY-MM-DD}_{slug}`；辅助指针} |

```



## 总纲条（如 B0）



允许在正文首段后加 **陷阱** 或短「公理支撑」列表；仍须过反常点测试。



## 收录后必做



1. 在 `经验/INDEX.md` 对应类别表追加一行（ID、链接、核心含义）。

2. 更新 INDEX 统计表条数。

3. 若本轮有剪裁，在 INDEX「整理记录 → 已删减」补一行。

4. 更新 `index.md` 经验入口（仅当新增类别或触发场景变化时）。

5. **（会议场景）** 同步完成 `项目大脑/团队经验/` 侧同等动作；团队条文须独立按本模板格式化，见 `team-experience-dual-write.md`。



## 禁止



- 主内容写「先…再…然后…」微操链

- `何时用到` 只写 `vision D2` 而无情境

- 把策划内共识、团队红线当个人反常点

- 与 `personal-axioms` 大段重复——可写公理号，不复制正文

- 把多条塞进一个主题聚合文件（已废弃；一律单篇 `entries/`）
