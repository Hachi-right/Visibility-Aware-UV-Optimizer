# 经验蒸馏方法论

> author: `team-lead`
> 用途: `personal-experience-curation` 的批量蒸馏、验证与收敛方法；单条零散沉淀只用 `curation-rules.md` 即可。
> 来源: YYYY-MM-DD 从外部三 workflow（认知画像提取 / 并行 subagent / 深度调研）蒸馏，适配项目大脑 task 素材（design.md + 当前 author口述，非聊天流水）。

## 1. 角色分工（Plan / Execute / Write / QA）

| 角色 | 谁做 | 说明 |
| --- | --- | --- |
| Plan | 主 agent | 每轮扫描维度、任务边界、验证设计 |
| Execute | sub-agent（可并行） | 扫 task、找证据、反例狩猎；产出是**原始素材**（task 路径+日期+原文摘录+候选认知），不是终稿 |
| Write | 主 agent | 条文正文、INDEX、整理记录 |
| QA | 主 agent | 交叉验证 sub-agent 结果、发现矛盾、判断收敛 |

**写作不外包（硬约束）**：所有 `entries/` 正文、INDEX、整理记录由主 agent 一人通稿。理由：条文间概念一致性、交叉引用精确性（B0 引 B4 的表述两边必须对齐）、文风统一（16 条读起来像一个人写的）。主 agent 的 context 花在设计与写作上，扫描检索外包。

## 2. 轮次结构与收敛判断

| 轮次 | 目标 | 动作 |
| --- | --- | --- |
| R0 广扫 | 候选条文池（宁多勿漏） | 按维度扫已完成 task → 候选清单 + 整理方案 → 当前 author确认划分 |
| R1 验证 | 淘汰弱证据 | 每条深挖证据链；跨 task 对比；时间稳定性；砍常识/共识 |
| R2 压力测试 | 修边界、防自相矛盾 | 反例狩猎（§5）+ 互斥性检验（§6）+ 预测力抽查（§7） |
| R3 定稿 | 通稿落盘 | 主 agent 写 entries + INDEX + 整理记录 → 当前 author过目 |

- 素材少（新增可扫 task < 5）：R0+R1 可合并、预测抽查可跳；**反例狩猎不跳**。
- **收敛信号**（满足 2 个即可定稿，勿追加轮次）：① 新找到的反例类型与之前重复；② 条目间关系稳定，不再需要合并/拆分/重组；③ 剩余修订不需要新素材即可直接执行。
- **过度迭代风险**：超过 3–4 轮，条文会从「可泛化认知」被磨成「对历史 task 的精确拟合」。宁留粗糙度，不过拟合。

## 3. 并行扫描规则（素材多时才用）

**触发**：待扫已完成 task ≥ 10 且维度可拆；否则主 agent 直扫，不为并行而并行。

- 3–5 个扫描维度（默认可用 A/B/C/D 类别）；维度间 **30–50% overlap**——同一 task 被两个维度覆盖时，不同解读或矛盾结论正是交叉验证点。
- 每个 sub-agent prompt 必含：负责维度与扫描范围、预期 overlap 区域、输出格式（task 路径 + 日期 + 原文摘录 + 候选认知一句话）。
- **不接受纯总结**——必须带原文摘录（拍板语句、design 决策原文）；转述无法验证。
- 第二轮起加**去重约束**：「前一轮已引用的证据不要重复」——迫使找新证据，对质量提升最大。
- 2–3 个精心设计的 sub-agent 优于 5 个松散的；中间结果不落盘，主 agent 整合后即弃。

## 4. 证据强度判定（跨源 + 时间）

| 证据形态 | 判定 |
| --- | --- |
| 同一判断在 ≥2 个独立 task/情境重复出现 | 稳定认知，可收录 |
| 只在单一 task 出现 | 可能是场景产物；留 task 决策文档，暂不进经验 |
| 当前 author口述校准 | 最高权重源；仍须写清当次情境（日期+争论） |
| 认知有演化（如 A5/B2 被校准） | 记录转折点与演化，不抹平历史；更新 `updated` 字段 |

多个独立来源方向一致但表述不同 → 更可能是真实认知；只在一种压力情境下出现 → 可能是当次表态，不是稳定判断。

## 5. 反例狩猎（每条必做）

- 每条候选**主动**找 ≥1 个反例：相反做法的 task、被翻案的拍板、当前 author自己没遵守的场景。
- 反例能被边界条件吸收 → 条文更精确，写进「边界」字段；这比堆正面证据有用得多。
- **完全找不到反例 → 警惕**：要么太泛（什么都能解释＝什么都预测不了，砍），要么证据不足（留 task 不进经验）。
- 出现一票否决级反例 → 砍或降级回 task 决策文档。
- 没有经过反例压力的条目只是观察，经过了才是经验认知。

## 6. 互斥性与条目关系

- 新条文入库前对照同类已有条目：**底层判断相同 → 合并**（哪怕表述不同）；**逻辑正交 → 独立**（哪怕领域接近）。
- 条目间张力不必消除——可用「默认模式 vs 边界模式」「描述性 vs 规范性」分层吸收；但须在两侧「边界」字段互注。
- 条目关系（闭环/张力/正交）维护在 INDEX「核心经验群」，每轮定稿时核一遍。

## 7. 预测力抽查（终极标准）

证据数量是中间指标；条文的最终价值是**能否预测当前 author在新争议上的判断方向**。

1. 挑 1–2 个未参与提炼的 task 或近期争议；
2. **先不看素材**，按条文做先验预测（判断方向、会否拍板、拍在哪层）；
3. 再对照实际拍板打分。

对不上时先查锚定层级（§8），而不是直接删条文。INDEX「主动检索触发」的关键词表就是预测力的日常运行形态——新增条文必须同步补触发词。

## 8. 锚定层级

- 条文锚定在**稳定的上位判断**，不锚定在具体方法。例：锚「验证是控制面」而非「TDD 是控制面」——上位概念能吸收方法论漂移，具体方法会被新情境击穿。
- 当前 author开始质疑某个具体方法但坚持上位概念时，条文锚上位概念。
- 与本 skill 口径同源：「要抽象工作思路（判断/意图），不要具体操作步骤」。

## 9. 陷阱对照表

| 陷阱 | 对策 |
| --- | --- |
| 条文太泛（追问：能预测什么？不能 → 非认知） | §7 预测力测试 |
| 条文太窄（会被下一个 task 击穿） | §8 提升锚定层级 |
| 证据选择偏差（只找支持项） | §5 反例狩猎强制对冲 |
| 跨条概念/措辞不一致 | §1 写作不外包，一人通稿 |
| 把当次表态当稳定认知 | §4 跨 task 对比 + 时间稳定性 |
| sub-agent 扫描太浅、只回总结 | §3 prompt 硬约束：原文摘录+路径 |
| 中间产物堆积污染私人区 | §3 只落 entries/INDEX/整理记录，扫描中间稿不落盘 |
| 过度迭代过拟合 | §2 收敛信号满足即停 |
