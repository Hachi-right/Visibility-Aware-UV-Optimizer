# 收件文件头格式

## 路径与命名

- 目录：`项目大脑/用户/{author}/收件/`
- 文件名：`YYYY-MM-DD-{topic}.md`

## 文件头（启动可读）

每份收件在正文前写文件头，以单独一行 `---` 结束。

### 必填字段

| 字段 | 说明 |
| --- | --- |
| Agent 阅读约束 | 明确写「启动时只读本文件头（至 `---` 为止）；不要读取分隔线以下正文，除非收件人明确说展开、读收件或指定本文件名」 |
| 状态 | `待处理` 或 `已处理` |
| 发件人 / 收件人 / 日期 | 若有临时替班或有效期，必须写明 |
| 一句话摘要 | 业务语言说明本件要收件人知道什么、是否需要行动 |

### 可选（仅 `待处理`）

- **待办或决策清单**：只列标题级条目，不展开细节。

### 拍板类 → team-lead 额外必填

主题含设计拍板、口径确认、执行决策二次确认时，文件头还须：

| 字段 | 说明 |
| --- | --- |
| 文档依据 | 权威设计文档路径 |
| 精神推导结论 | 按文档精神推导出的结论 |
| 仍须拍板原因 | **为空则不应发送**（说明文档已足够自行落地） |

发件前必须先执行 `design-advisor-lens`，并在当前任务 `process.md` 写入「主创侧面参考（非拍板）」。

## 已处理精简文件头

状态为 `已处理` 时，文件头**只保留**：

- Agent 阅读约束
- 状态
- 处理日期
- 结论落盘（已沉淀的 task / `经验/` / `docs/` 路径）
- 一句话结论

**禁止**保留：背景段、待办清单、决策选项表、拍板过程。处理完成后立即压缩。

## 正文（确认后可读）

`---` 以下写完整汇报、对齐说明或交接正文。agent 在用户确认前不得为执行任务而读正文。已处理的详细过程保留在正文区，不回流到文件头。

## 沉淀

收件人确认展开后，稳定结论沉淀到 task `process.md` / `design.md` 或 `经验/`；沉淀完成后改 `已处理` 并压缩文件头。
