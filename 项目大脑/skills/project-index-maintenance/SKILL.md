# project-index-maintenance

本 skill 维护公共 `项目大脑/index.md` 和私人 `项目大脑/用户/{author}/index.md` 的规模。一级索引只做入口，不做长清单；新增后将超过 50 条或已经超过 50 条时，自动分级，不把“超过 50 条”本身当成错误。通用分类方法先看 `index-tiering-methodology`，本 skill 只负责 `index.md` 的脚本化执行和验证。

## 使用流程

1. 运行 `scripts/check_index_size.py --repo-root . --auto-split`，确认公共和私人一级索引条目数，并自动分级超阈值索引。
2. 如果目标索引新增后不超过 50 条，直接追加“路径 + 触发式摘要”。
3. 如果目标索引新增后会超过 50 条，先按 `index-tiering-methodology` 确认稳定主题和分类名，再建立二级索引：
   - 公共二级索引放 `项目大脑/索引/{category}.md`。
   - 私人二级索引放 `项目大脑/用户/{author}/索引/{category}.md`。
4. 一级 `index.md` 只保留分类入口，指向二级索引；二级索引保存具体文档、目录或 skill 入口。
5. 相关文档也按分类整理到子文件夹；已有稳定归属的目录不强行移动，例如 `docs/meeting/`、`docs/顶层设计/`、私人 `经验/`、`tasks/`。
6. 更新当前任务 `process.md`，写清自动分级原因、分类名、移动/未移动的文档、索引位置和验证结果。

## 分类规则

- 分类名要稳定、短、能从任务语义猜到内容，例如 `公共规则`、`会议资料`、`顶层设计`、`公共skills`、`私人经验`、`交付规则`。
- 不按日期、任务编号、临时标题或单条文档名建分类。
- 同一主题已有二级索引时，追加到已有文件，不新建近义分类。
- 一级索引分类入口也计入 50 条；二级索引也按同一阈值控制，继续膨胀时再细分。

## 写法

一级索引保留分类入口：

```markdown
| `索引/会议资料.md` | 会议资料二级索引；整理会议转写、会议纪要和会议共识。 |
```

二级索引保存具体入口：

```markdown
# 会议资料索引

> 用途: 会议转写、会议纪要和会议共识的二级索引。

| 文档 | 用途 |
| --- | --- |
| `../../docs/meeting/YYYY-MM-DD_主题.md` | 何时披露；解决什么问题。 |
```

## 禁止事项

- 不把文档正文复制进索引。
- 不为每个文档创建一个二级索引。
- 不把私人资料移动到公共区；不跨 author 整理其他人的私人索引。
- 不移动已有明确归属的任务目录、经验目录或 docs 领域目录，除非用户明确要求。

## 脚本行为

- `scripts/check_index_size.py` 默认只输出索引规模，不因超阈值返回失败。
- 带 `--auto-split` 时，脚本按一级索引里的二级标题自动拆到 `索引/{category}.md`，并修正二级索引中的相对路径。
- 只有显式传 `--fail-on-oversized` 时，仍然存在超阈值索引才返回非 0。
