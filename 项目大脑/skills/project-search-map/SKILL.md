# 项目搜索地图

本 skill 是搜索前的总入口。它不替代 `project-code-map`，而是先判断“要找的是什么”，再把搜索导向正确地图、索引和工具。

## 搜索顺序

1. 确认当前 author 和当前任务目标。
2. 判断目标类型：代码、文档、配置/表格、脚本、资源、会议、设计思想。
3. 先查当前 author 私人 `资料地图/index.md`，再查公共 `资料地图/index.md`。
4. 如果目标是代码、接口、函数、调用链或相似实现，转入 `project-code-map`；先用私有/公共代码地图产出查询规划卡，再带地图锚点用 CodeGraph / `rg` 验证。
5. 如果目标是设计文档、会议记录、规则文档或外部资料，先查公共/私人 `index.md`，再用 `rg --files` / `rg` 在稳定目录内搜索。
6. 如果目标是配置、表格、脚本或静态资源，先查资料地图的对应主题，再用 `rg --files` / `rg` 在稳定目录内搜索。
7. 找到稳定入口后，只更新当前 author 私人 `资料地图/`；公共资料地图由 leader 周期抽取。

## 类型路由

| 目标类型 | 优先入口 | 兜底工具 |
| --- | --- | --- |
| 代码、接口、调用链、相似实现 | `project-code-map`（查询规划卡：私有地图/差异列表 -> 公共地图 -> 带锚点 CodeGraph/`rg` 验证）、`docs/规则/index.md` | 限定目录 `rg` |
| 配置、表格、导表、JSON 数据 | `资料地图/`、`docs/project-data-standards.md`、`docs/agent工作规则.md` | `rg --files data config tools`、表格工具 |
| 业务脚本、回调、自定义函数 | `资料地图/`、`docs/规则/index.md` → `脚本与框架边界.md` | `rg "call_|data/scripts|scripts"` |
| 静态资源、媒体、静态资源 | `资料地图/`、`assets/`、`tools/`、`frontend/` 相关入口 | `rg --files assets tools frontend` |
| 会议记录、录音转写 | 公共/私人 `index.md`、`docs/meeting/` | `rg` |
| 设计思路、顶层设计、规则文档 | 公共/私人 `index.md`、`docs/顶层设计/`、设计文档目录 | `rg` |

## 资料地图写入

资料地图记录“非代码资料在哪里找、如何顺藤摸瓜、哪些目录和文件是稳定入口”。代码位置仍写代码地图。

当前 author 搜索到稳定非代码入口后，写入 `项目大脑/用户/{author}/资料地图/{主题}.md`，并更新 `资料地图/index.md`。主题按资料类型聚类，例如 `文档与会议.md`、`配置与表格.md`、`脚本与回调.md`、`静态资源.md`、`设计思路.md`。

记录字段建议：

- 最后更新时间：`YYYY-MM-DD`
- 最后验证版本：git commit 短哈希或分支基准
- 适用场景：什么问题先看这里
- 稳定入口：目录、文件、表格名、配置 key、资源 key、云文档标题或会议标题
- 查找经验：从需求、UI、配置 id、资源名、会议关键词或设计术语如何定位
- 相关代码地图：需要代码时指向 `代码地图/` 主题
- 来源任务：当前任务目录或稳定复盘来源

## 禁止事项

- 不把文档正文、会议正文、配置正文或长日志复制进资料地图。
- 不一条搜索一个文件；按主题聚类。
- 不记录容易漂移的行号；必要时记录标题、表名、配置 key、资源 key 或稳定符号。
- 不把未入库外部资料直接写成稳定入口；先入库或写明来源和可访问方式。
- 不跨 author 写私人资料地图。
